## 真实双机验收

用户已在两台保留各自 Mineradio 登录数据的 Windows 设备上完成 2.4.0 端到端验收，以下场景通过：

- 创建房间、授权加入、不同账号配对与同平台同 UID 拒绝。
- 两人配对后暂停并进入等待首曲；任一方选择第一首后开始同步。
- 播放、暂停、手动切歌、进度拖动和当前歌曲状态同步。
- 双方头像、昵称、会员标识、文字聊天与消息提示。
- 主动断开后恢复进入联机前的队列并保持暂停，随后可由用户恢复单人播放。

本记录表示上述实际验收路径已经通过，不代表所有公网运营商、FRP 节点、音乐版权限制或极端网络抖动均已覆盖。

## 启动烟雾测试

注入后的临时 Mineradio 已进入本地服务启动和 startup window 的 `dom-ready` / `did-finish-load` 阶段。当前执行环境随后因 Chromium GPU 子进程缺少可用图形运行时而退出（`GPU process isn't usable`）；这是测试宿主限制，未观察到注入代码语法错误或主进程模块加载失败。

## 其他观察

- 旧版 `test-sync-engine.js` 属于已停用的 WebRTC CoPlay v2 实现，单独运行时为 3 通过、1 失败；新版 manifest 不安装该实现，正式 `npm test` 不再把它作为当前模块验收测试。
- 为执行新版源码自带测试，在新版源码目录运行过 `npm install --ignore-scripts`，生成了被项目忽略的 `node_modules`；未修改两个 Mineradio 项目的业务源码。
- 依赖安装报告 27 项上游审计告警（12 moderate、14 high、1 critical），未自动执行可能产生破坏性升级的 `npm audit fix --force`。
