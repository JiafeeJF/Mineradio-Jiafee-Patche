# Mineradio 多功能补丁器

当前版本：**2.4.0** · JIAFEE 开发 · [GitHub Releases](https://github.com/JiafeeJF/Mineradio-Jiafee-Patche/releases/latest)

面向 Mineradio 2.2.0 的 Electron 本地补丁工具，包含两个互不依赖的模块：

- 音效增强：Jiafee 音效预设、10 段均衡器和 Web Audio 处理链。
- 一起听联机：从新版 Mineradio 源码整理出的 TCP/IP 双人同步、局域网免码加入、公网授权码、重连、头像和文字互动。

## 2.4.0 更新

- 一起听资料自动读取 Mineradio 当前登录的网易云或 QQ 音乐账号；网易云优先，昵称、头像和 VIP/SVIP 标识无需二次登录。
- 连接首包携带经过本体账号接口确认的平台和 UID。同平台、同 UID 的双方会在进入双人同步前立即拒绝连接；不同平台及明确未登录的访客不受影响。
- TCP/WebSocket 建链后等待服务端权威房间状态确认，再向界面报告连接成功，避免账号校验尚未完成时误报已连接。
- 房间只有一人时保留原播放队列和播放状态；两人真正配对后才进入等待首曲状态。主动退出、同账号拒绝或重连彻底失败时恢复进入联机前的队列，并保持暂停，避免无声自动播放。
- 统一消息序列化字节预算、发送失败处理、重连与身份状态清理，降低超限消息污染房间状态的风险。
- 一起听资料不可手动修改，头像下载与身份校验解耦；聊天、头像区、VIP 标识和玻璃面板继续沿用现有交互。

## 使用

1. 运行 `npm start`，或启动 `dist` 中构建好的安装包。
2. 选择 Mineradio 2.2.0 源码根目录，或已安装程序的根目录。
3. 勾选音效增强、一起听联机，或同时勾选两个模块。
4. 点击“检查兼容性”，通过后点击“开始注入所选模块”。
5. 一起听模块会同时写入 `ws ^8.22.0` 声明和运行时文件；源码项目如需更新 lockfile，可再运行 `npm install --package-lock-only`。

一起听的“保存地址”会直接保存当前地址并以地址作为默认名称，不会保存授权码。点击已保存的局域网地址可免码加入；点击公网、DDNS、FRP 或回环代理地址时，需先在直连区填写 6 位授权码。

主动断开一起听或连续 3 次重连失败后，补丁会释放一起听的媒体、队列和加载状态，再恢复原版单人播放控制；短暂断网和自动重连期间不会提前清空会话。

一起听头像区下方的聊天输入栏可用 `∧/∨` 收起和展开。对方发送消息时会播放一声约 0.2 秒的低音量柔和提示音；断线重连后文字消息通过独立事件通道恢复，不依赖播放状态版本变化。

一起听面板位于桌面标题栏 DIY 按钮旁，使用与音效弹层一致的冰灰边框、24px 模糊和分层阴影，并采用更通透的黑色玻璃底。面板仍可滚动，但不显示右侧滚动条；创建/加入与联机房间之间会连续过渡，头像区断开时会先淡出再移除。

## Docker 一起听中转服务

`together-relay-server` 提供与补丁内一起听协议兼容的独立 Docker 服务。一台容器对应一个双人房间，用户在一起听面板中输入服务器 `域名:端口`（或 `IP:端口`）和部署时设置的 6 位授权码即可加入，不需要 `wss://` 前缀。2.4.0 客户端支持原生 TCP 地址识别和同账号入房校验。服务端只处理中转和权威播放状态，不传输音乐音频，也不持久化用户数据。

```bash
cd together-relay-server
cp .env.example .env
# 修改 .env 中的 AUTHORIZATION_CODE
docker compose up -d --build
```

完整部署、端口、防火墙和反向代理说明见 `together-relay-server/README.md`。

Windows 服务器也可安装 Release 中的 `Mineradio-Together-Relay-Control-1.0.2-Setup.exe`，通过图形界面配置授权码、监听地址并启动、停止和查看中转服务状态。1.0.2 已内置账号校验运行时；控制端源码位于 `together-relay-server/windows-control`。

“卸载所选模块”只删除所选模块自己的标记块和资源；另一个已安装模块会被保留。再次安装同一模块用于更新，标记块不会重复插入。

## 备份和回滚

模块记录位于目标目录的 `.jiafee-<模块 ID>-patch.json`，原文件备份位于 `.jiafee-patches/<模块 ID>/original`。记录包含目标版本、模块版本、时间、文件清单及原始 SHA-256。

注入先在内存中生成所有文件结果，所有锚点、资源和版本检查通过后才写入。如果写入发生异常，本次变更按逆序恢复。卸载使用独立标记移除共享文件中的增量代码，并按模块恢复或删除自身资源。

## 关于 2.3.0 版本下架的说明

大家好，我是 JIAFEE。

由于 Mineradio 多功能补丁器 2.3.0 在一起听功能的账号识别、连接校验及断开恢复方面存在稳定性问题。为避免继续影响使用，我已下架 2.3.0 版本。由此给大家带来的困扰，我在这里真诚地说一声抱歉。

新版本增加了同账号检测：如果一起听双方使用同一音乐平台的同一个账号，系统会拒绝连接并自动断开。这样处理是为了避免同一账号在多台设备上同时使用可能引发的账号风控、平台规则及音乐版权风险。该限制只比较“音乐平台和用户 ID”，不会上传账号密码、Cookie 或 Token，也不会保存授权凭据。

建议仍在使用 2.3.0 的用户尽快卸载旧版本并更新至最新版。感谢大家的理解、反馈与支持，我会继续完善一起听功能的稳定性和使用体验。
