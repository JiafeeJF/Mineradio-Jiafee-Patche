# Mineradio 多功能补丁器

面向 Mineradio 2.2.0 的 Electron 本地补丁工具，包含两个互不依赖的模块：

- 音效增强：Jiafee 音效预设、10 段均衡器和 Web Audio 处理链。
- 一起听联机：从新版 Mineradio 源码整理出的 TCP/IP 双人同步、局域网免码加入、公网授权码、重连、头像和文字互动。

## 使用

1. 运行 `npm start`，或启动 `dist` 中构建好的安装包。
2. 选择 Mineradio 2.2.0 源码根目录，或已安装程序的根目录。
3. 勾选音效增强、一起听联机，或同时勾选两个模块。
4. 点击“检查兼容性”，通过后点击“开始注入所选模块”。
5. 一起听模块会同时写入 `ws ^8.22.0` 声明和运行时文件；源码项目如需更新 lockfile，可再运行 `npm install --package-lock-only`。

一起听的“保存地址”会直接保存当前地址并以地址作为默认名称，不会保存授权码。点击已保存的局域网地址可免码加入；点击公网、DDNS、FRP 或回环代理地址时，需先在直连区填写 6 位授权码。

主动断开一起听或连续 3 次重连失败后，补丁会释放一起听的媒体、队列和加载状态，再恢复原版单人播放控制；短暂断网和自动重连期间不会提前清空会话。

一起听头像区下方的聊天输入栏可用 `∧/∨` 收起和展开。对方发送消息时会播放一声约 0.2 秒的低音量柔和提示音；断线重连后文字消息通过独立事件通道恢复，不依赖播放状态版本变化。

一起听面板位于桌面标题栏 DIY 按钮旁，使用与音效弹层一致的冰灰边框、24px 模糊和分层阴影，并采用更通透的黑色玻璃底。面板仍可滚动，但不显示右侧滚动条；创建/加入与联机房间之间会连续过渡，头像区断开时会先淡出再移除。

## Docker 一起听中转服务

`together-relay-server` 提供与补丁内一起听协议兼容的独立 Docker 服务。一台容器对应一个双人房间，用户在一起听面板中输入服务器 `IP:端口` 和部署时设置的 6 位授权码即可加入。服务端只处理中转和权威播放状态，不传输音乐音频，也不持久化用户数据。

```bash
cd together-relay-server
cp .env.example .env
# 修改 .env 中的 AUTHORIZATION_CODE
docker compose up -d --build
```

完整部署、端口、防火墙和反向代理说明见 `together-relay-server/README.md`。

“卸载所选模块”只删除所选模块自己的标记块和资源；另一个已安装模块会被保留。再次安装同一模块用于更新，标记块不会重复插入。

## 备份和回滚

模块记录位于目标目录的 `.jiafee-<模块 ID>-patch.json`，原文件备份位于 `.jiafee-patches/<模块 ID>/original`。记录包含目标版本、模块版本、时间、文件清单及原始 SHA-256。

注入先在内存中生成所有文件结果，所有锚点、资源和版本检查通过后才写入。如果写入发生异常，本次变更按逆序恢复。卸载使用独立标记移除共享文件中的增量代码，并按模块恢复或删除自身资源。

## 开发和构建

```powershell
npm test
npm run build:win:dir
npm run build:win
```

目录构建在 `dist/win-unpacked`，NSIS 安装包在 `dist`。

## 验证范围

`test-together-enhancements.js` 覆盖局域网免码、公网鉴权边界和互动动画资源；`test-multifunction.js` 覆盖仅音效、仅一起听、组合安装、重复安装、逐个卸载及原始哈希恢复。一起听协议/服务/播放器适配继续使用新版源码自带的 `tests/together-listen-*.test.js` 测试集。

真实双设备、FRP 公网链路及受限歌曲仍需要两台 Windows 设备、有效网络隧道和对应音乐平台账户，无法由本地单机自动化替代。

详细资料见 `docs/SOURCE-DIFF-REPORT.md`、`docs/MODULES.md` 和 `docs/TEST-RESULTS.md`。
